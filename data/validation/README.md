# Validation Dataset

This folder is the local place for validation videos, labels, configs, human evidence, and generated review outputs.

Simple meaning: when we test OpenFloodAI on sample videos, keep the input files, human notes, and system output in a clear structure instead of mixing them together.

## Folder Layout

Use one folder per site:

```text
data/validation/
  sites/
    example-site/
      configs/
      videos/
      labels/
      human-evidence/
        flood-images/
        notes/
      outputs/
        records/
        summaries/
        operator-notes/
        review-images/
```

For real validation work, create a site folder with a safe short name:

```text
data/validation/sites/colorado-river-windy-gap/
data/validation/sites/bagmati-river-demo/
data/validation/sites/koshi-river-demo/
```

## What Goes Where

`configs/` keeps site and camera config files.

Simple example: a config can say which camera ID was used and which `reference_region` should be watched.

`videos/` keeps local validation videos.

Simple example: one short clip from a river camera can live here while a developer tests the POC locally.

`labels/` keeps human labels.

Simple example: a reviewer may label a time window as `normal water`, `rising water`, `high water`, `unclear view`, or `camera moved`.

Use JSON Lines for labels, with one label record per line.

Safe example:

```json
{"video_id":"demo-river-001","time_window_seconds":[0,30],"human_label":"water_rising","confidence":"medium","note":"Water appears to move higher against the bridge pillar."}
```

Allowed `human_label` values are:

- `water_rising`
- `water_falling`
- `no_clear_change`
- `camera_video_problem`
- `cannot_judge`

See the Human Label Format documentation for the full field list and validation command.

After a local POC run, compare labels with system output using the Human Label Comparison guide.

Simple example: compare `labels/example-labels.jsonl` with `outputs/records/run-001.jsonl` to see whether the human label and system visual-change result agree.

`human-evidence/flood-images/` keeps images selected by a person as possible flood or high-water evidence.

Simple example: a reviewer sees a frame where water looks high and saves that frame here for later comparison.

`human-evidence/notes/` keeps simple human review notes.

Simple example: `The water is close to the lower bridge marker at 00:17.`

`outputs/records/` keeps JSON Lines records created by local POC runs.

`outputs/summaries/` keeps readable summary reports.

`outputs/operator-notes/` keeps plain-language output notes.

`outputs/review-images/` keeps images generated by OpenFloodAI, such as baseline, changed, and comparison images.

## Human Evidence Compared With System Output

Keep human-selected images separate from system-generated review images.

Simple example:

```text
human-evidence/flood-images/
  frame-human-says-high-water.png

outputs/review-images/run-001/
  review-baseline.png
  review-changed.png
  review-comparison.png
```

This lets us compare:

```text
Human reviewer: this frame looks risky.
OpenFloodAI POC: this frame had the biggest selected-region change.
```

That comparison will help later with labels, QA, and ML training.

## Privacy Rules

Do not commit private real videos or real camera images by default.

Good to commit:

- this README
- `.gitkeep` placeholder files
- safe synthetic examples
- public documentation

Do not commit by default:

- real private camera videos
- real flood images from private cameras
- exact sensitive GPS coordinates
- private camera URLs
- generated review images from real footage
- personal contact details

Simple rule: if a file came from a real place or a real camera, keep it local unless it is clearly approved for public use.

## Current Boundary

This folder structure does not add flood detection, ML training, alerts, cloud upload, live cameras, or a database.

It only creates a safe place to organize future validation data and review outputs.
